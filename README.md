# SmartOps Agent · 智能运维故障诊断多 Agent 协同系统

> 面向光伏 / 储能场站的故障诊断智能体：把「问题归属判断 — 案例检索 — 处置生成 — 反馈学习」做成一条可评估、可迭代的自动化链路。

## 为什么做这个

新能源场站的运维一线有一个高频但低效的环节：**故障问题单的归属判断**。

一条故障描述往往横跨多个专业领域——功率异常可能来自能量调度策略、电池簇不一致、通信链路中断或逆变器故障。工程师必须凭借个人经验翻手册、查历史工单、问老师傅，平均 **30 分钟到 2 小时** 才能确定"这问题该交给哪个部门"。资深工程师的经验留在人脑里，人一走就断档。

SmartOps Agent 要解决的就是这件事：**输入一句自然语言的故障描述，系统自动完成理解、归属判定、证据检索、处置建议，并把人工修正沉淀回知识库。**

### 三个核心设计

**1. 三层路由漏斗（确定性优先）**

| 层级 | 机制 | 适用场景 | 成本 |
|------|------|---------|------|
| ① 规则引擎 | 正则 / 关键词匹配 | 高频确定性故障（覆盖约 60%） | 毫秒级，零模型成本 |
| ② RAG 投票 | Top-5 案例中 ≥3 条同归属才判定 | 有历史案例的常见故障 | 一次向量检索 |
| ③ LLM 兜底 | 强制从预设部门集合中选择 | 模糊 / 新型故障 | 一次模型调用 |

> 设计原则：**能规则不模型、能检索不生成**——把昂贵的模型调用留给真正需要语义理解的样本。

**2. 混合检索 + RRF 融合**

- **BGE-large-zh** 向量召回：解决语义泛化（"功率不足"能召回"出力偏低"）
- **BM25** 关键词召回：解决精确值问题（向量对 `40001 ≈ 40002` 天然不敏感）
- **结构化精确直查**：告警码 / 设备编号 / 寄存器地址
- **RRF（k=60）** 融合：不同检索分数量纲不可比，只利用排名信息
- **Cross-Encoder** 精排：粗排保召回、精排保准确

**3. 置信度门禁与反馈闭环**

- 综合置信度 = 路由置信度 × 0.6 + 检索匹配度 × 0.4，阈值 **0.7**
- 高于阈值 → 自动生成结构化工单；低于阈值 → 转专家研判（**宁可多让人看一眼，不可错发工单**）
- 人工修正结果经幂等机制（`doc_id = fb_ + diagnosis_id`）与部门白名单校验后回写知识库，**系统越用越准**

### 工程化能力

- **结构化输出约束**：Pydantic schema 校验（枚举 + 自定义 validator），校验失败带错误信息重试，二次失败降级并显式记录
- **MCP 工具封装**：日志分析、寄存器查询等能力以标准工具形式暴露（描述即文档 / schema 严格 / 错误结构化）
- **全链路 Trace**：每个诊断任务可回溯到节点级的输入输出与决策
- **服务化与部署**：FastAPI 接口 + Gradio 界面 + Docker 容器化
- **可观测**：降级路径强制打日志（踩过「静默兜底导致评估假象」的坑后立的规矩）

## 评估结果

| 指标 | 结果 |
|------|------|
| 路由归属准确率 | **83%** |
| Top-3 召回率 | **100%** |
| 字段完整率 | **83%** |
| 规则层覆盖 | 约 60%（零模型成本） |
| 端到端效率 | 归属判断从 30min–2h → **3 分钟内**人机协同 |

评估方式：分类测试集（精准 / 理解 / 边界三类场景）+ 自动化跑批 + bad case 分层归因（数据层 / 检索层 / 模型层 / 护栏层）。

## 快速开始

```bash
# 1. 安装依赖（torch 建议按 CUDA 版本单独安装）
pip install -r requirements.txt

# 2. 配置环境变量
cp .env.example .env
# 填入 LLM API Key（DeepSeek / OpenAI 兼容端点均可）

# 3. 运行主流程验证
python main.py

# 4. 启动 Web 界面
python app.py

# 或使用 Docker
docker compose up -d
```
